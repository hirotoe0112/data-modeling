## レビュー観点

以下の観点で詳細にレビューを行ってください。

### 1. 要件との整合性
- 背景・概要に記載されたユースケースをデータモデルで実現できているか
- 抜けているエンティティや属性はないか

### 2. エンティティ設計
- エンティティが実世界の概念を適切に表現しているか
- エンティティの粒度（細かすぎ・粗すぎ）は適切か
- エンティティとイベントの区別が適切か（リソース系 vs イベント系）

### 3. 正規化
- 第1正規形（1NF）: 繰り返しグループや複数値属性がないか
- 第2正規形（2NF）: 複合主キーに対する部分関数従属がないか
- 第3正規形（3NF）: 推移関数従属がないか

### 4. 関係性の定義
- カーディナリティ（1対1、1対多、多対多）は正確か
- 必須/任意（ゼロ以上か1以上か）の設定は適切か
- 多対多関係に中間テーブルが必要な場合、適切に設計されているか

### 5. 属性の設計
- NULL許容の判断は適切か（NULL許容を避ける設計ができているか）
- データ型の選択は適切か
- 主キーの選択は適切か（代理キー vs 自然キー）
- 命名規則は一貫しているか

### 6. 実装上の考慮点
- インデックスが必要になりそうなカラムはあるか
- 論理削除が必要か
- 楽観的ロック・排他制御の必要性

### 7. 拡張性
- メモに記載された将来の拡張案に対応できる設計か
- 変更に強い設計になっているか

### 8. SQLアンチパターンの照合
以下の代表的なアンチパターンに該当する要素がないか確認し、該当するものがあれば指摘してください。該当しないものは「該当なし」で簡潔に触れてください。

| アンチパターン名 | 概要 |
|---|---|
| ジェイウォーキング (Jaywalking) | 1カラムにカンマ区切りで複数値を格納している |
| ナイーブツリー (Naive Trees) | 親IDのみで階層構造を表現しており、深い階層の取得が困難 |
| IDリクワイアド (ID Required) | 全テーブルに意味のないサロゲートキーを追加し、本来の自然キーを主キーにしていない |
| キーレスエントリ (Keyless Entry) | 外部キー制約を設定しておらず、参照整合性をアプリ任せにしている |
| EAV (Entity-Attribute-Value) | 属性名・属性値を汎用テーブルに格納しており、型安全性や検索性が低下している |
| ポリモーフィック関連 (Polymorphic Associations) | 1つのFKカラムが複数のテーブルのどれかを指す設計で、参照整合性を保てない |
| マルチカラムアトリビュート (Multi-Column Attributes) | `tag1, tag2, tag3` のように同種の属性を複数カラムで表現している |
| メタデータトリブル (Metadata Tribbles) | 月別・年別などでテーブルやカラムを増殖させている |
| フロートで金額 (Use Float for Money) | FLOAT/DOUBLE型で金額や精度が重要な数値を管理している |
| ファントムファイル (Phantom File) | ファイルパスや外部リソースのパスをDBに格納しているが、ファイル自体の管理が保証されていない |

## 出力形式

以下の形式でレビュー結果を出力してください：

### 総評
（モデル全体の評価を2〜3文で述べる。「自分で気づいた」「改善できた」など作者の行動・過程へのコメントは不要）

### 良い点
- 具体的な箇条書きで（なぜ技術的に良いかを述べる。設計の内容を評価する。作者の行動・過程への言及は不要）

### 改善点・問題点
各項目に深刻度 🔴高 / 🟡中 / 🟢低 をつけて箇条書きで

### SQLアンチパターン照合結果
該当するアンチパターンを指摘し、該当しないものは簡潔にまとめる

### 具体的な改善提案
改善後のER図（Mermaid形式）や修正案を具体的に示す

### 学習のポイント
このモデルを通じて学べるデータモデリングの概念や原則

## レビュー完了後の保存

レビューが完了したら、結果を以下のルールでファイルに保存してください：

- 保存先: `reviews/` ディレクトリ（存在しない場合は作成する）
- ファイル名: レビュー対象ファイルの名前をベースに `-review.md` を付加する
  - 例: `2025-07-09-tea.md` → `reviews/2025-07-09-tea-review.md`
- 保存内容: レビュー結果の全文（対象ファイル名・レビュー日時のヘッダーを冒頭に付ける）
- 保存後に「`reviews/〇〇-review.md` に保存しました」と報告する
